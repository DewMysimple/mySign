# 参考视频逐帧分析与实现对应

已解码并检查连续的 **557 帧**，不是只检查几张代表截图。全部帧的连续图组在 `contact-sheets/`，逐帧测量及人工阶段标注在 `frame-metrics.csv`，代表画面在 `keyframes/`。

## 1. 素材与检查方法

| 项目 | 实测 |
| --- | --- |
| 视频尺寸 | 2504 × 1616 |
| 帧率 | 30 FPS |
| 可解码视频帧 | 557 帧，编号 F000–F556 |
| 视频帧覆盖时长 | 557 / 30 ≈ 18.567 秒 |
| MP4 容器时长 | ffprobe 报告约 18.576 秒；音频轨使容器略长 |
| 最后一帧起始时间 | F556 ≈ 18.533 秒 |
| 首个可分割蓝色笔迹 | F089 ≈ 2.967 秒 |
| 完整停留时蓝色像素 | F390 约 94,237 像素 |
| 粒子阶段蓝色像素峰值 | 129,599 像素，不能将其误认为签名更长 |

每一帧都经过解码，记录时间、蓝色区域面积、包围盒、与前帧的灰度差。然后按帧号制作 8 张连续图组，每张最多 72 帧；逐一检查笔尖、蓝线、阴影、按钮和输入框的变化。为了核对形体和笔迹，另外查看全分辨率关键帧。

CSV 的 `visual_phase`、`visible_prefix_target`、`observation` 是依据画面做的人工解释；字母阶段是近似区间，不能当作原应用内部状态或精确笔画边界。笔尖会遮住新墨迹，投影和视频压缩也会影响蓝色分割，因此蓝色像素数量不等于路径长度。测量列与解释列分开保留。

## 3. 画面的空间关系

### 大面积留白

背景基本为均匀浅灰白，没有标题、导航、说明卡片或其他视觉中心。原视频初始笔尖约在画面宽度的 68%、高度的 50% 附近；输入区域中心约在高度的 76% 附近。完成的签名横向占画面约 64%，主体位于中部偏上。网页采用相同的布局关系，短姓名自然缩短，长姓名自动缩小并居中。

### 笔杆与笔尖

笔杆投影大体从左下指向右上，角度变化克制；并不会每遇到一个字母转圈。铅笔的大部分体积可越出画面，尖端仍然必须与书写位置对应。笔尖接触点是运动枢轴，旋转和抬笔都围绕这个枢轴计算，不能将笔杆中心当作文字端点。

视频只能证明其视觉上呈现立体笔杆，无法从成片确认原作者使用了什么具体技术。Three.js、SVG、GSAP 是本项目依据要求选定的实现，不是从视频反推出的原工程信息。

### 真实跟随的阴影

阴影从笔尖附近向右下展开，远端边缘更软。它跟随笔的位移和高度变化，提供接触与悬空的线索。固定的 CSS 阴影或单独平移的静态灰图无法保持这种空间关系。

实现以 XY 作为纸面，Z 作为高度：正交相机沿 Z 看向纸面，SVG 的屏幕 X/Y 可直接转换到 Three 世界坐标。方向光与接收阴影平面生成真实阴影贴图，再作 32 次采样的面积光近似。纸面从 VSM 的深度投射中排除，避免扩大采样核时将倾斜接收面误判成遮挡物。采样循环展开以消除本机显卡的纹理导数编译警告。

## 4. 最关键的同步关系

不能只让一个笔模型横向滑动，再让字体独立出现。正确的数据链是：

1. 姓名生成有序的单线笔画。
2. GSAP 当前时间确定当前笔画及其路径进度。
3. 同一个进度更新 SVG `stroke-dashoffset`。
4. 用同一 SVG 路径的 `getPointAtLength()` 得到当前端点与局部切线。
5. 用统一的布局变换将端点映射到屏幕和 Three 正交世界。
6. 将真实石墨顶点所在的模型原点放到该位置，再渲染铅笔和阴影。

字体只是整体的蓝色图形还不够。本实现的 52 个字母都是手工定义的中心线路径，点和横画有独立笔顺；小写字母间距允许时添加连接笔画，其他位置抬笔。字形不是从字体的封闭轮廓提取，所以不会沿每个字母的外圈走两遍，也没有使用“完整文字 + 水平遮罩”的降级方案。

## 5. 消散与重置

视频中擦除一开始蓝色分割面积反而上升，说明线条周围产生了扩散的蓝色细粒，而非仅降低整行字的透明度。网页沿已经完成的 SVG 中心线取样，将粒子初始位置散布在笔画宽度内，通过一个 Canvas 绘制数千个小点。

清除 Timeline 同时控制笔迹消失、粒子扩散和铅笔返回；结束时释放粒子与路径，再清空输入、恢复焦点和 idle 状态。普通模式清除约 1.3 秒；低动态模式使用较短的线条淡出，不生成飞散粒子。

## 6. 与参考和照片提示的对应

| 参考要求 | 实现 |
| --- | --- |
| 先把白背景、3D 笔、柔影、输入及签名区做好 | 无多余页面内容，构图和光照集中在这几个元素 |
| 优先解决笔尖与笔迹同步 | 独立检查真实 SVG dash 端点与 3D 投影，不能仅检查控制器自己的坐标 |
| 自然节奏和状态变化 | 先移到起点、按弧长书写、短暂抬笔、完成停留、按钮切换 |
| 清除也是交互的一部分 | 粒子采样、笔归位、清输入、恢复输入焦点统一编排 |
| 支持不同名字，不写死 Shakespeare | 52 个大小写字形、空格、字宽、基线、连笔及真曲线边界 |
| 真实交互而非静态视觉 | 浏览器里完成输入、书写、再次输入与多轮清除；无视频/截图驱动的页面 |

## 7. 核验依据与已知边界

- `verification/desktop-writing.png`：中途笔画，而非完整文字淡入。
- `verification/desktop-written.png`、`desktop-amy.png`：不同长度的真实生成结果。
- `verification/desktop-particles.png`：实际粒子清除过程。
- `verification/mobile-written.png`、`mobile-initial.png`：窄屏完成和归位后的构图。
- `verification/long-name.png`：长姓名的缩放与居中。
- `verification/synchronization.json`：桌面 1337 个独立采样，最大数学投影误差约 0.0011 CSS px。
- `verification/responsive.json`：书写中多次调整窗口，262 个采样，最大误差约 0.00064 CSS px。
- `verification/playwright-results.json`：完整浏览器自动化结果，3 项通过；另有 5 项模型测试通过。
- `verification/production-smoke.json`、`production-desktop.png`、`production-mobile.png`：实际生产构建在设备像素比 2 下完成书写与清除，调试接口未暴露，控制台无错误或警告。
- `verification/glyph-atlas.png`：52 个实际单线字形的逐个视觉核对图。

测试在本机 Chrome、Windows、WebGL 环境执行。数学投影误差不是像素抗锯齿误差，采样到的帧间隔也不是所有设备的性能保证。复写前后的 Three 几何体数量保持 8、纹理数量保持 4；静止状态没有继续渲染。

原视频使用的字体/手写数据未知，本实现因此保留核心交互和视觉关系，采用一套原创固定风格的单线字形；不承诺与原视频字体逐像素一致。目前只支持 ASCII 英文字母与空格，中文及其他符号不在该字形库内。
