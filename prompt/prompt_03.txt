# Shakespread 中文硬笔行书视觉原型开发任务书

## 一、项目任务

你现在需要对 Shakespread 项目进行一次中文书写视觉体系升级。

本次任务的核心不是增加中文输入功能，也不是重新开发中文笔画引擎，而是解决目前最明显的产品问题：

**现有中文虽然能够按照笔顺逐笔显现，也能驱动 3D 铅笔运动，但整体视觉效果仍然像标准印刷字体被程序逐笔绘制，缺乏真实硬笔手写的自然感。**

我希望将中文书写效果升级为：

**中度行书化的硬笔行书（Hard-Pen Running Script）。**

目标是让用户看到的中文更接近真人使用一支硬笔自然书写出来的效果，而不是标准字体的路径动画。

本次先完成高质量视觉原型，不直接批量改造全部 3500 个汉字。

首要任务是让「你好」两个字达到理想效果。

## 四、正式确定中文视觉风格

本项目采用：

**硬笔行书 + 中度行书化。**

具体视觉特征如下。

### 4.1 自然起笔

避免所有笔画都以完全相同的机械形态开始。

允许根据笔画类型表现：

- 轻微顿笔。
- 自然入锋。
- 适度尖锋。
- 轻微倾斜。
- 自然的墨迹起始形态。

### 4.2 自然行笔

书写过程中需要表现：

- 轻微粗细变化。
- 自然弧度。
- 转折时的力度变化。
- 不同笔画之间的节奏变化。
- 合理的书写倾向。

不要让每一笔都像通过统一参数生成的标准几何图形。

### 4.3 自然收笔

根据不同笔画类型处理：

- 提笔。
- 顿笔。
- 出锋。
- 回锋式收笔。
- 自然尖尾。

避免所有笔画都采用机械截断的方式结束。

### 4.4 自然连带

允许相邻笔画之间出现符合硬笔行书规律的自然连带。

例如：

- 前一笔收笔自然带向下一笔。
- 相邻笔画之间出现合理的牵丝。
- 某些连续动作不必完全停顿后再重新落笔。
- 在适合的地方进行有限的局部简化。

但是不能为了追求连贯而任意改变汉字结构。

### 4.5 字形整体姿态

适当调整：

- 字形倾斜。
- 左右结构比例。
- 上下结构比例。
- 字形重心。
- 笔画松紧。
- 字形整体视觉节奏。

所有字形必须保持同一套书写风格。

不能出现「你」字像行书，而「好」字又像印刷楷体的情况。

## 五、建立原型字与部件级风格规则

本次采用：

**高质量原型字 + 部件级风格规则 + 批量生成 + 人工修正。**

但当前只实施原型阶段。

### 5.1 首批原型

优先完成：

- 你
- 好

这两个汉字是本次视觉验收的核心。

「你」重点考察：

- 单人旁的自然书写。
- 左右结构的空间关系。
- 撇、竖等笔画的自然连带。
- 右侧部件的笔势和重心。

「好」重点考察：

- 女字旁的行书表现。
- 女字旁与子部件之间的空间关系。
- 转折和钩画的自然形态。
- 左右结构的整体协调。

两个汉字必须具有一致的笔迹风格。

### 5.2 初步建立基础笔画风格规则

围绕以下笔画建立统一的硬笔行书表现：

- 横。
- 竖。
- 撇。
- 捺。
- 点。
- 提。
- 折。
- 钩。

每种笔画都需要明确：

1. 起笔形态。
2. 行笔曲线。
3. 粗细变化。
4. 转折方式。
5. 收笔形态。
6. 中线轨迹。
7. 对应的完整轮廓。

这些规则必须从实际原型字中提炼，不要先建立一套没有经过视觉验证的抽象参数体系。

### 5.3 建立部件风格规则

本次至少研究：

- 亻。
- 尔。
- 女。
- 子。

重点不是简单复用印刷字体的偏旁轮廓，而是理解这些部件在硬笔行书中的自然书写方式。

后续其他汉字应当能够复用这些规则。

## 六、非常重要：逻辑笔画与实际书写动作必须分离

这是本次架构设计中的关键要求。

中度行书化允许笔画自然连带，但不能因此丢失汉字原有的逻辑笔画信息。

因此必须区分：

### 6.1 逻辑笔画层

负责记录：

- 原始逻辑笔画编号。
- 原始笔画顺序。
- 对应字形部件。
- 笔画来源。
- 结构信息。

### 6.2 视觉书写动作层

负责记录：

- 实际铅笔运动轨迹。
- 自然连接关系。
- 牵丝和过渡。
- 落笔与抬笔。
- 连续动作分组。
- 对应的完整墨迹区域。

例如，两个逻辑笔画在行书中可以形成一个连续书写动作，但仍然保留各自的逻辑编号和对应关系。

不能简单地把两笔合并后删除原始笔画信息。

如果某个行书方案涉及主体笔画省略或实质性笔顺变化，必须单独标记、说明依据并进入人工复核，不允许静默改变。

## 七、建立真正的硬笔行书字形数据

这是本次开发最重要的技术任务。

不能只在现有标准字形上增加：

- CSS 倾斜。
- 随机弯曲。
- 统一粗细变化。
- SVG 滤镜。
- 随机扰动。
- 简单路径平滑。

这些方法只能改变外观，不能真正改变汉字的书写形态。

### 7.1 原有数据的作用

现有 HWD 主数据源与 MMH 备用数据源继续作为：

- 字形结构参考。
- 原始逻辑笔画顺序参考。
- 笔画位置参考。
- 数据来源和许可追踪依据。

不能直接把标准轮廓当作最终的行书轮廓。

### 7.2 原型字形需要独立的艺术化数据

针对「你」和「好」，建立独立的行书原型数据。

每个逻辑笔画或书写动作至少具有：

- 完整 SVG 轮廓。
- 对应中线轨迹。
- 逻辑笔画编号。
- 视觉动作编号。
- 连接关系。
- 起点和终点。
- 轨迹长度。
- 局部坐标。
- 字形边界。
- 前进宽度。
- 基线偏移。
- 粗细和起收笔参数。
- 数据来源与修改记录。

轮廓和中线必须经过对应关系检查。

不能使用一条普通字体轮廓，再随意生成一条铅笔运动轨迹。

### 7.3 外部字体和素材

可以研究合法可用的硬笔行书字体或书写参考，帮助建立视觉风格。

但必须：

- 检查许可证。
- 记录来源和版本。
- 不下载来源不明的字体。
- 不将缺少笔顺和中线的普通字体轮廓直接当作完整书写数据。
- 不引入运行时在线字体依赖。
- 不破坏现有 Arphic Public License 相关数据的来源记录。

外部字体可以辅助视觉研究，但不能自动证明它具有正确的书写顺序。

## 八、与现有动画系统集成

必须保留现有：

`SignatureController.js`

它仍然是唯一的 GSAP 动画协调层。

### 8.1 3D 铅笔

3D 铅笔必须沿新的行书中线运动。

重点检查：

- 笔尖是否始终落在实际墨迹路径上。
- 转折是否自然。
- 连带动作是否连续。
- 抬笔时是否出现合理的移动。
- 铅笔倾斜是否与实际运动一致。

### 8.2 完整笔画显现

继续使用完整笔画轮廓和动态遮罩。

不能把完整汉字替换成细线书写。

笔尖沿中线运动时，完整轮廓必须根据共享动作进度逐渐显现。

对于连带笔画，应当根据真实书写动作组织显现顺序。

### 8.3 动画时间

重新校准中文行书的动画节奏。

不能简单地让所有笔画使用相同速度。

需要根据：

- 中线长度。
- 曲线复杂度。
- 转折。
- 连带。
- 起笔与收笔。
- 抬笔类型。

调整动作时长。

笔尖、墨迹、阴影必须继续共享统一动作进度。

### 8.4 清除动画

保留现有橡皮擦功能。

清除粒子必须从实际完整可见的行书轮廓区域采样，而不是只从中线采样。

铅笔归位和清除过程不得受到新字形结构影响。

## 九、调整产品输入与排版范围

本项目现在明确采用桌面端单行签名。

### 9.1 不再开发多行排版

取消：

- 自动换行。
- 多行签名。
- 8 行限制。
- Shift+Enter 手动换行。

签名区域固定为单行。

桌面 Enter 提交，中文输入法组合期间 Enter 仍交由输入法处理。

如果输入内容包含不支持的换行，应明确提示并保留原文，不得静默删除。

### 9.2 输入长度限制

不允许为了容纳过长文本而无限缩小字号。

建立明确的可配置输入限制，综合考虑：

- 最大字符数量。
- 单行实际可用宽度。
- 最小可读字号。
- 实际笔画数量。
- 预计动画时长。
- 桌面渲染性能。

具体数值通过实际原型校准，不得随意拍定。

超过限制时：

- 拒绝本次提交。
- 保留原文。
- 明确说明超限原因。
- 允许用户修改后重新提交。

不自动截断，不自动换行。

### 9.3 手机端

本次完全不考虑手机端优化。

以桌面 Chrome/Chromium 为主要开发和验收环境，保留现有必要的桌面浏览器回归。

## 十、原型实现方式

### 第一阶段：建立风格规范

先不要修改正式 3500 字字库。

根据「你」和「好」建立一份中文硬笔行书视觉规范。

明确：

- 笔画粗细。
- 起笔和收笔。
- 转折方式。
- 自然连带。
- 笔画倾斜。
- 字形重心。
- 部件比例。
- 字间视觉关系。

### 第二阶段：制作两个高质量行书字形

完成独立的：

- 「你」字形数据。
- 「好」字形数据。

要求它们在静态状态下就具有明显的硬笔行书特征。

不要依赖动画效果掩盖字形本身的问题。

### 第三阶段：接入现有动画系统

让用户在当前网页输入「你好」时，能够真正看到新的中文行书原型。

使用现有 3D 铅笔、阴影、GSAP 时间线和完整轮廓显现机制。

不要为了原型增加多余的产品 UI。

如果需要原型切换或调试入口，只能采用开发环境专用方式，不能把调试控件带入正式生产界面。

### 第四阶段：进行视觉对比

至少生成以下材料：

1. 现有标准中文「你好」完整截图。
2. 新硬笔行书「你好」完整截图。
3. 新字形各笔画轮廓图。
4. 中线与完整轮廓叠加图。
5. 3D 铅笔书写过程关键帧。
6. 完整书写动画的浏览器录制或等效证据。
7. 新旧效果对比报告。

必须在真实浏览器中观察效果，而不是只看 SVG 文件。

## 十一、视觉验收标准

本次增加独立的视觉验收，不能只以代码测试通过作为完成依据。

| 验收项目 | 标准 |
|---|---|
| 手写感 | 明显摆脱标准印刷字体观感 |
| 起笔 | 有自然的落笔形态 |
| 行笔 | 有合理的粗细与曲线变化 |
| 转折 | 自然，不出现机械折线感 |
| 收笔 | 有自然的提笔或出锋 |
| 连带 | 相邻笔画具有合理的书写连续性 |
| 字形 | 仍然能够清楚识别 |
| 一致性 | 「你」与「好」像同一套书写风格 |
| 铅笔 | 笔尖始终跟随真实轨迹 |
| 墨迹 | 完整轮廓与笔尖运动同步 |
| 清除 | 完整轮廓能够正确消散 |

特别注意：

视觉验收不允许通过降低笔顺正确性、破坏汉字结构或偏离中线来换取艺术效果。

Codex 的自动图集审查不能冒充人类书法专家的全面认证。

最终需要保留截图和动画证据，供用户进行审美验收。
