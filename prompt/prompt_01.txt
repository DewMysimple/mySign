你是一位擅长 React、Vite、Three.js、SVG、GSAP 和实时交互视觉设计的高级创意前端工程师。请在当前项目中实现一个参考视频的交互式 3D 签名网页。

第一步：检查项目目录、package.json、现有页面、依赖和开发服务器启动方式。理解现有工程后再修改，不要覆盖无关页面，不要只输出方案或伪代码。保持现有技术栈，必要时新增依赖需说明原因。

一、视觉目标
构建一个极简、接近产品摄影质感的全屏签名网页。背景使用柔和的暖白或浅灰白色。画面中央偏上的区域是大型蓝色手写签名；一支放大的白色 3D 铅笔从右上方斜向伸入画面。画面下方偏中间放置一个白色胶囊形输入框，右侧为圆形操作按钮。不要增加标题、导航栏、卡片、介绍文字或多余 UI。保持大量留白。整体风格干净、安静、克制，重点是铅笔、笔迹和光影。

二、3D 铅笔与光影
使用 Three.js 创建真正的程序化 3D 铅笔，不要用静态 PNG 代替。由笔杆、笔尾、笔尖和石墨尖端等几何部件组成。笔杆采用接近白色的细腻材质，利用适当的 roughness、灯光、正交相机和柔和投影表现圆润体积。构建接收阴影的书写平面，合理配置阴影贴图、环境光和方向光，形成明显但柔和的灰色投影。铅笔主体可部分超出画面右上边缘。书写时笔尖必须与当前笔迹终点对齐，铅笔移动时阴影同步变化。不要让笔尖与文字明显错位。

三、输入与交互状态
使用 React 管理 idle、writing、written、erasing 状态。初始时输入框为空，用户可以输入任意英文姓名。输入框支持 Enter 键提交，按钮支持鼠标点击。空输入不得启动动画。书写过程中禁用重复提交，并显示简洁的加载状态。书写结束后，按钮变为橡皮擦图标。点击橡皮擦后触发粒子消散，动画完成后清空输入框，铅笔返回初始位置，页面恢复到 idle 状态。必须支持连续多次输入、书写、清除，不得因为重复点击产生多个冲突动画。

四、手写笔迹引擎
优先使用真正的单线手写字体或按笔画顺序定义的 SVG 路径。输入英文名字后，生成与当前文字相对应的书写路径。支持大小写英文字母和空格，正确处理不同字母的宽度、间距、连笔、基线和整体居中。使用 SVG path、stroke-dasharray、stroke-dashoffset 等方式逐渐显示路径，并通过 getPointAtLength 或等效方法计算当前书写位置。笔迹使用清晰、自然的蓝色，线条粗细与参考视频接近。不得将单词写死为 Shakespeare，不得只使用逐字显示的打字机动画，不得把完整文字直接淡入。

如果无法找到可用的单线手写字体或笔画路径资源，先评估可用的合法字体和现有依赖，再使用手写字体结合 SVG 遮罩渐进显现作为降级方案。此时铅笔尖必须跟随实际的揭示进度，避免描绘普通字体的外轮廓。请明确说明该降级方案与真实笔画路径的区别。

五、铅笔与笔迹的同步
将书写路径的进度作为统一的动画数据源。每一帧根据当前路径进度计算笔尖位置，并同步更新 Three.js 中铅笔的位置。根据路径切线适当调整铅笔倾角，但保持整体斜向姿态自然，不要随每个字母剧烈旋转。使用统一的 SVG viewBox、屏幕坐标映射和 Three.js 正交相机坐标转换，保证不同屏幕尺寸下笔尖与笔迹一致。不要使用两个互不关联的定时器分别移动铅笔和显示文字。

六、GSAP 动画编排
使用 GSAP Timeline 统一控制完整交互流程。用户确认名字后，按钮进入加载状态，铅笔移动至第一个笔画的起点，随后开始书写。书写速度自然，允许不同笔画之间有极短的节奏变化。书写结束时铅笔停在最后一个笔画的终点，按钮切换为橡皮擦。清除时让蓝色笔迹破碎成细小粒子，粒子向外轻微扩散并逐渐消失，同时铅笔平滑回到初始位置。粒子可以基于 SVG 路径采样生成，优先使用 Canvas 或 Three.js Points 等轻量实现，不要为每个粒子创建大量独立 DOM 元素。避免生硬的突然位移、过度弹跳和夸张缓动。

七、页面布局与适配
采用全屏、极简构图。签名在画面中央偏上，输入框位于下方偏中间，铅笔从右上方进入。保持充足留白，避免文字被铅笔遮挡。使用 clamp、百分比或合理的响应式布局处理字号和间距。监听画布尺寸变化，正确更新 Three.js 相机、渲染器和坐标映射。在窄屏幕上保证签名、输入框和按钮可见。考虑 prefers-reduced-motion，提供适当的低动态效果。

八、工程结构与性能
将页面 UI、签名路径生成、Three.js 铅笔场景和 GSAP 动画逻辑合理拆分。复用渲染器，不要在每次 React 渲染时重复创建 Three.js 场景。正确管理 requestAnimationFrame、事件监听器、GSAP Timeline 和资源清理。避免内存泄漏和 React StrictMode 下的重复初始化。尽量复用现有依赖，不要引入不必要的大型库。

九、实际验收
完成后启动项目现有开发服务器并实际检查页面。至少验证：初始空白状态、输入 Shakespeare 后提交、笔尖与书写路径同步、完整签名停留、橡皮擦触发粒子消散、铅笔归位、再次输入不同长度的英文名字、连续清除与重写、窗口缩放。检查控制台报错、WebGL 性能和文字裁切问题。不要只生成一个静态视觉模型，也不要以截图、录屏或预渲染视频代替真正的实时交互。
