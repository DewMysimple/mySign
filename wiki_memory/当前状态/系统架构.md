# 系统架构

## 模块职责与边界

纯客户端 React / Vite / Three.js / GSAP，无后端、账户、持久化或新依赖。本轮运行时源码只改变 xingshuRegistry 两个 JSON 导入；Controller、motionRhythm、输入、布局、英文、renderer、模型及粒子均沿用。

- designs.mjs：两字独立 A/B 中线、逐笔压力、节奏与部件设计；build-xingshu-v2 生成候选和最终数据、图集、独立源码 / 许可发布副本。
- xingshu-connection-audit：独立六条件准入，拒绝三个旧返回线和未知连续组。最终只有子部直接接触，13逻辑 / 12组 / 13墨迹段。
- xingshuRegistry：深度不可变的两字实验覆盖，不改正式 manifest。GlyphLoader / 双层 LRU 继续负责其余3498字；两字无需fetch或正式分片pin。
- writingPlan：单行预检与统一动作计划；每段使用实际中线和同一视口映射。
- SignatureController：唯一GSAP时钟，共享进度驱动完整轮廓、3D笔尖、阴影、接触与抬笔、故障和清除。
- inkRenderer / scene：原渲染、真几何 / 柔影 / 完整区域粒子实现；本轮源码不变。

## 数据流与依赖

原文 → 注册表预检 → 实验两字或本地标准字lease → 单行预算 → 固定墨迹 / 空中移动计划 → 实际SVG弧长 → 同一GSAP进度驱动遮罩、Three笔尖与阴影。删除牵丝后实际路径就是13段；没有隐藏连接残留。

好4→5共点(69.4,35.6)、共向切线、共宽1.9；其余11次笔间移动真实离纸。清除继续从实际完整轮廓区域采样，之后归位。写完保留签名到用户清除，沿用既有交互。

正式字库仍独立分片，两字新数据随JS；编辑源码、审查记录、来源与APL随public/experiments/xingshu-v0.2.0分发。旧v0.1.0和analysis/xingshu冻结。HWD只作原逻辑顺序 / 结构参考，未用字体轮廓或随机变形。

## 运行与部署

Node22.12+，npm ci、npm run dev；build / preview及测试命令见README。候选研究服务器只在开发阶段替换两个JSON导入，产品没有模式开关。原型数据只从本地加载，不上传输入。

本轮模型、Chromium、其他桌面、生产、显现与校准实际执行。verify-xingshu-v2-acceptance --check只读检查报告指纹与保护范围，不重跑浏览器；数据变更需重新验证。
