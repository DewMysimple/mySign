按 wiki-memory 3.2.1 完成只读初始化预览及应用，接入根目录 `AGENTS.md`，保留项目独立可用的维护协议、工具和 schema 2 配置。五份状态页依据实际源码、原始提示词和验证报告填写；六类日志目录用 `.gitkeep` 保留，本次只写一份 maintenance 日志，不编造其他类型历史。

根指令记录用户的持续约束：每次完整对话有项目修改就提交并推送，无需重复请求许可；无修改不制造空提交。收尾核对实际远程 SHA，不强推、不覆盖无关修改、不虚报成功。

## 实际操作与验证

- 环境核对：Windows / PowerShell，Python 3.14.2、Node 24.16.0、npm 12.0.1、Git 2.54.0。
- 实际运行 Skill 的 `init --mode standard` 预览，再加 `--apply` 应用，均成功。后续使用项目工具副本，不依赖个人 Skill 安装位置。
- 运行 `git init --initial-branch=main` 并添加指定 `origin`。启用项目本地 `core.longpaths` 支持原视频长文件名；`.gitattributes` 统一文本换行，命令脚本 CRLF，媒体按二进制跟踪。
- 应用、视频、提示词与分析成果形成首次提交 `43260659c13d074b4a50d03f4576fcbf4bab1948`。提交前 `git diff --cached --check` 通过；未提交依赖、dist 或测试临时文件。
- `git push --set-upstream origin main` 成功，随后 `git ls-remote origin refs/heads/main` 与该基线一致。记忆及根规则通过后续维护提交交付，最终 HEAD 以收尾实际远程复核为准。
- 核对了历史浏览器报告的 3 项通过、0 失败，以及同步与生产预览报告。未修改应用源码，未为写记忆重新运行业务测试；不把前轮报告当作未来分支的自动验收。

工程记忆的完整验收使用 `python "wiki_memory/工具/memory.py" index --project . --apply` 和 `python "wiki_memory/工具/memory.py" check --project . --require-ready`。人工核对五页各节、来源与模式合同，不能以生成模板代替实质记忆。
